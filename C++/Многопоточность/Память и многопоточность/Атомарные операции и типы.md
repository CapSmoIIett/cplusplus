# Multithreading

**Атомарные** — неделимые операции

Ни из одного потока в системе невозможно увидеть, что такая операция выполнена наполовину — она либо выполнена целиком, либо не выполнена вовсе.

---

# Атомарные типы в C++

## std::atomic

`std::atomic<T>` — шаблонный тип из заголовка `<atomic>`, обеспечивающий атомарный (неделимый) доступ к переменной типа T между потоками.

### Основные свойства
- Гарантирует отсутствие гонок данных при одновременном доступе из нескольких потоков.
- Операции чтения, записи, обмена и арифметики выполняются атомарно.
- Поддерживает примитивные типы (int, bool, указатели и др.), а также пользовательские типы, удовлетворяющие требованиям TriviallyCopyable.

### Примеры объявления
```cpp
#include <atomic>
std::atomic<int> counter{0};
std::atomic<bool> flag{false};
std::atomic<void*> ptr{nullptr};
```

### Основные методы
- `load()` — атомарное чтение
- `store()` — атомарная запись
- `exchange()` — атомарная замена значения
- `compare_exchange_weak/strong()` — атомарное сравнение и обмен (CAS)
- Операторы ++, --, +=, -= и др. (если поддерживаются для типа T)

### Memory order (порядок памяти)
- По умолчанию используется `memory_order_seq_cst` (самый строгий порядок).
- Можно явно указывать порядок: `relaxed`, `acquire`, `release`, `acq_rel`, `seq_cst`.
- Порядок памяти определяет, как операции видны между потоками (важно для производительности и корректности).

### Пример использования
```cpp
#include <atomic>
#include <thread>

std::atomic<int> counter{0};

void increment() {
    for (int i = 0; i < 1000; ++i) {
        counter.fetch_add(1, std::memory_order_relaxed);
    }
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);
    t1.join();
    t2.join();
    // counter == 2000
}
```

### Типичные сценарии применения
- Счётчики, флаги, индикаторы состояния между потоками
- Реализация lock-free структур данных
- Примитивы синхронизации (spinlock, флаги готовности и др.)

### Важно
- std::atomic не заменяет все случаи использования мьютексов, но позволяет избежать блокировок в простых сценариях.
- Для сложных структур данных и операций часто требуется дополнительная синхронизация.
