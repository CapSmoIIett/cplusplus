# Multithreading

**Livelock** – очень похож на [[Deadlock]], с той лишь разницей, что во время livelock’а потоки во время ожидания выполняют какие-то операции. Однако эти операции не имеют практического смысла, так как потоки несмотря на выполняемые операции и так не могут завершить свои задания.

## Определение
Livelock — ситуация, при которой потоки не блокируются окончательно (как при deadlock), а продолжают активно изменять своё состояние в ответ на действия других потоков, но не могут продвинуться к завершению работы.

## Признаки livelock
- Потоки не простаивают, а активно работают (например, пытаются захватить ресурс, отпускают его и снова пытаются).
- Система не делает полезной работы, несмотря на отсутствие блокировки.

## Пример livelock
```cpp
#include <mutex>
#include <thread>

std::mutex m1, m2;
bool done = false;

void thread1() {
    while (!done) {
        if (m1.try_lock()) {
            std::this_thread::yield(); // уступаем управление
            if (m2.try_lock()) {
                // критическая секция
                done = true;
                m2.unlock();
            }
            m1.unlock();
        }
    }
}

void thread2() {
    while (!done) {
        if (m2.try_lock()) {
            std::this_thread::yield();
            if (m1.try_lock()) {
                // критическая секция
                done = true;
                m1.unlock();
            }
            m2.unlock();
        }
    }
}
```
В этом примере оба потока постоянно пытаются захватить мьютексы, уступают управление, но могут бесконечно "уступать" друг другу, не продвигаясь к завершению.

## Отличие от deadlock
- При deadlock потоки полностью блокируются и не выполняют никаких действий.
- При livelock потоки продолжают работать, но не могут завершить задачу.

## Как избежать livelock
- Вводить случайные задержки (backoff) перед повторной попыткой захвата ресурса.
- Использовать строгий порядок захвата ресурсов.
- Минимизировать количество повторных попыток без прогресса.

## Типичные сценарии возникновения
- Использование try_lock в цикле без задержек.
- Взаимные уступки между потоками (оба потока "вежливо" уступают друг другу).

## Важно
- Livelock может быть сложнее обнаружить, чем deadlock, так как потоки не простаивают, а активно работают.
- Для диагностики полезно использовать профилировщики и анализаторы многопоточных программ.
