# Асинхронные сокеты

**Асинхронная работа с сокетами** — это способ организации сетевого взаимодействия, при котором операции ввода-вывода (I/O) не блокируют выполнение программы, позволяя эффективно обслуживать множество соединений.

---

## Основные подходы к асинхронной работе

### 1. Неблокирующие сокеты
- Сокет переводится в неблокирующий режим (non-blocking), операции `read`/`write`/`accept`/`connect` возвращают управление сразу, даже если операция не завершена.
- Для отслеживания готовности используют дополнительные механизмы (см. ниже).

### 2. Мультиплексирование ввода-вывода
- Позволяет одному потоку отслеживать множество сокетов и реагировать на события (готовность к чтению/записи).
- Основные API:
  - **select** — кроссплатформенный, но ограничен по количеству дескрипторов.
  - **poll** — снимает часть ограничений select, но менее эффективен на большом числе соединений.
  - **epoll** (Linux) — масштабируемый, эффективен для тысяч соединений.
  - **kqueue** (BSD, macOS) — аналог epoll для BSD-систем.
  - **io_uring** (Linux, C++20+) — современный высокопроизводительный интерфейс для асинхронного I/O.
  - **IOCP (I/O Completion Ports)** (Windows) — высокоэффективный механизм асинхронного I/O.

### 3. Асинхронные API высокого уровня
- Библиотеки: Boost.[[Asio]], libuv, cppcoro, Qt Network, POCO и др.
- Позволяют писать кроссплатформенный асинхронный код с удобным интерфейсом.

---

## Пример: неблокирующий сокет и select (POSIX)
```cpp
#include <sys/socket.h>
#include <fcntl.h>
#include <sys/select.h>

int sock = socket(AF_INET, SOCK_STREAM, 0);
fcntl(sock, F_SETFL, O_NONBLOCK); // неблокирующий режим

fd_set readfds;
FD_ZERO(&readfds);
FD_SET(sock, &readfds);
select(sock+1, &readfds, nullptr, nullptr, &timeout);
if (FD_ISSET(sock, &readfds)) {
    // сокет готов к чтению
}
```

## Преимущества асинхронных сокетов
- Высокая масштабируемость: один поток может обслуживать тысячи соединений.
- Эффективное использование ресурсов (CPU, память).
- Подходит для серверов реального времени, чатов, прокси, веб-серверов.

## Недостатки и сложности
- Более сложная логика обработки событий (state machine).
- Необходимость учитывать edge-triggered/level-triggered режимы (epoll, kqueue).
- Труднее отлаживать и тестировать по сравнению с блокирующими сокетами.

## Особенности реализации
- Важно правильно обрабатывать частичные операции чтения/записи.
- Для масштабируемости часто используют event loop (цикл обработки событий).
- В современных C++-фреймворках (Boost.Asio, cppcoro) поддерживается асинхронность на основе coroutines.

## Важно
- Асинхронные сокеты — стандарт для высоконагруженных сетевых приложений.
- Выбор подхода зависит от платформы, требований к производительности и удобству разработки.
